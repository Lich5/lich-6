# 5.21.0 baseline preservation

The working tree reconciles upstream tag `v5.21.0`
(`526ad7cd011d689e8bdf41328c91b049ec145ec7`) with the existing R3 main
(`a25aade03c1087267d8082e798d2ff5c82b46273`). The shared ancestor is
`284849923698bf56619ddd9f8fa7b54d26bebe02`. Git history is unchanged.

Upstream inventory, combat, creature definitions, CLI commands, authentication
fallback, frontend configuration, and active-session directory changes carry
forward. The Ruby version file advances to 4.0.5 because that is part of the
upstream baseline, not as a local testing workaround. Gemfile.lock is unchanged.

R3's native WebUI startup, authentication boundary, security contract, and removal
of core GTK remain. In particular:

- The renamed frontend registry retains R3's toolkit-independent refocus callback.
- The newer ordered combat worker uses Ruby compaction without the removed toolkit
  compaction helper.
- Non-Windows message reporting retains R3's stderr behavior.
- Session spawning combines custom frontend identifiers and inherited active-session
  directories with R3's explicit parent data-directory propagation.
- Game names move out of the removed graphical selector into LoginHelpers. New
  selections follow 5.21.0's valid game codes; historical saved-entry labels remain.
- Removed graphical files remain removed. The new upstream graphical frontend tab
  and manual selector are conversion references, not core runtime dependencies.
  Their UI-specific tests need native equivalents with the Frontend-tab change.

Upstream CRLF source files were normalized to LF; seven surplus blank lines were
removed to satisfy the existing lint configuration. No functional cleanup was
performed in creature data.
